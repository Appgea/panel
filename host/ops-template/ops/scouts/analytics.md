---
title: Where does the path from install to the first purchase stop?
who: a new user between the install and the first payment. Evidence: the funnel numbers and the code that leads to the paywall.
every: routine
agent: claude
---

Lens: one person, from the first open to the first time they pay. Each step either moves them on or loses them.
The step that loses the most becomes a finding, with its number. Read only. One app a run: `analytics@<App>`.
Before the install is the `stranger` lens. After the first payment is `keeper`. Whether a purchase delivers is `money-links`.

Abilities, in `scouts/abilities/`:
- `funnel-numbers`: the analytics funnel, read in the analytics console. The one ability here that needs a browser.
- `zero-earner`: an app that earns nothing, walked in the code from launch to the buy button, to the first step that cannot work.
- `paywall-moment`: where the first paywall comes against the first value, and screens with no way to buy.
- `price-ladder`: the plans on the paywall beside each other: order, default, saving and trial, as the code shows them.
- `event-truth`: the funnel events, checked against the moment each should count.

Yours to add when all of them ran on the app: what else stops a new user before the first payment. For example, an
onboarding that asks for a permission before it shows any value, a free tier so full that nothing is left to buy, a
locked feature with no preview, or an offer that ends before a new user can meet it.

A finding: a step between install and first purchase that loses people or cannot be finished, at `path:line` or with
its funnel number. A price change is the owner's call: file it as a question.
Not a finding: a step that already converts, a taste call on paywall art, a number from a window that holds an old build.
