Lens: a change or feature the market rewards, not a defect. Four known paths, so the same miss is not found again by hand.

1. The run names the app. Read `apps/<key>.md` and the app's store listing.
2. Take the rivals from the app's own store page: the "You might also like" row. Those are the rivals to hold it against.
3. Run each path below. A path with no finding writes nothing.

## Paths

- A. Progress that never shows: the main screen does not change with how long the user has kept going.
  Finding only when the main screen shows no state that grows with use, and a rival in the row shows one.
- B. The rating or paywall comes before any value.
  Finding only when the paywall shows before any feature works, or the rating prompt fires before a good moment.
  Check `direction.md` first: a deliberate early paywall is not a finding.
- C. A feature the rivals lead with is missing.
  Finding only when the code and the store text have no trace of it, and a store search for the term shows rated rivals.
- D. A control or clutter the rivals let the user choose.
  Finding only when the element takes a large part of the first screen, no setting turns it off, and a rival offers that choice.

At most 1 idea a run. Search the backlog for the same idea first.
Not a finding: a trend no rival in the category shows, a copy of one rival's feature, a change for its own sake.
An idea the owner said no to stays dead unless its premise changed. Read only: no store or app change.
